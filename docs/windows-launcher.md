# Windows desktop launcher

Документ описывает эксплуатацию дипломного проекта через Windows GUI-лаунчер без ручной работы с терминалом.

## Где находится лаунчер

- Исходник: `launcher/launcher.py`
- PyInstaller spec: `launcher/launcher.spec`
- Скрипт сборки exe: `scripts/build-launcher.ps1`
- Лог работы: `launcher.log` в корне проекта
- PID/state файл: `.launcher/state.json`

Лаунчер ищет проект рядом с exe или на уровень выше. Для эксплуатации проще положить `DiplomLauncher.exe` в корень проекта рядом с папкой `apps`.

## Реальные команды проекта

Backend (`apps/api`):

- production build: `npm run build`
- production start: `npm run start`
- проверка БД: `npm run db:check` с SQL `SELECT 1;` через stdin
- миграции: `npm run migrate:deploy`
- seed дефолтного администратора: `npm run seed:admin`
- demo seed: `npm run seed:demo`
- создание администратора: `npm run admin:create`

Frontend (`apps/web`):

- production build: `npm run build`
- production start: `npm run start`

Если на компьютере установлен `pnpm`, лаунчер использует его. Если `pnpm` не найден, используется `npm` внутри `apps/api` и `apps/web`.

## Как запускается проект через GUI

1. Откройте `DiplomLauncher.exe` или запустите исходник командой `py -3 launcher/launcher.py`.
2. На вкладке **Запуск** нажмите **Запустить проект**.
3. Лаунчер выполнит шаги:
   - проверит подключение к PostgreSQL;
   - выполнит `prisma migrate deploy`;
   - выполнит seed дефолтного администратора;
   - при отсутствии production-сборки соберет backend/frontend;
   - запустит backend и frontend в production-режиме.
4. После запуска используйте кнопку **Открыть сайт в браузере**.

Лаунчер не создает дубликаты процессов: если backend/frontend уже запущены этим лаунчером, повторный запуск будет пропущен.

## Как остановить проект

На вкладке **Запуск** нажмите **Остановить проект**. Лаунчер завершит процессы backend и frontend, которые были им запущены, включая дочерние процессы Node.js.

## Настройки базы данных

Настройки находятся на вкладке **Настройки**:

- `DB_HOST`
- `DB_PORT`
- `DB_NAME`
- `DB_USER`
- `DB_PASSWORD`

Проект Prisma использует `DATABASE_URL`, поэтому лаунчер обновляет `DATABASE_URL` и синхронизирует рядом переменные `DB_*` в `apps/api/.env`.

Перед каждым изменением `.env` создается backup рядом с файлом:

```text
apps/api/.env.backup-YYYYMMDD-HHMMSS
```

Лаунчер обновляет только нужные переменные и не затирает файл полностью. Пароль БД не выводится в интерфейс логов и не записывается в `launcher.log`.

## Дефолтный администратор

Дефолтный администратор задается через `apps/api/.env`:

```env
ADMIN_EMAIL=admin@zskills.local
ADMIN_PASSWORD=change_me_admin_password
ADMIN_NAME=Admin User
```

`ADMIN_PASSWORD` нужен только для создания дефолтного администратора. Если администратор с `ADMIN_EMAIL` уже существует, seed не создает дубль и не сбрасывает пароль. Если `ADMIN_PASSWORD` не задан, но в базе уже есть любой пользователь с ролью `ADMIN`, seed также не блокирует запуск.

Seed можно запустить из вкладки **Администраторы** кнопкой **Запустить seed администратора**.

## Как добавить администратора

1. Откройте вкладку **Администраторы**.
2. Укажите имя, email/login и пароль.
3. Нажмите **Добавить администратора**.

Лаунчер передает пароль служебному Prisma-скрипту через переменную окружения процесса. Пароль не хранится в коде и не пишется в логи.

Перед созданием выполняется проверка существующего пользователя:

- если администратор с таким email уже есть, дубль не создается;
- если email занят пользователем с другой ролью, создание отменяется;
- если email свободен, создается пользователь с ролью `ADMIN` и bcrypt-хешем пароля.

## Доступ из локальной сети

Backend слушает `0.0.0.0:<PORT>`, frontend слушает `0.0.0.0:3000`.

На вкладке **Запуск** лаунчер показывает:

- локальный адрес: `http://localhost:3000`
- адрес в локальной сети: `http://<local-ip>:3000`

Чтобы открыть сайт с другого компьютера:

1. Убедитесь, что оба компьютера в одной локальной сети.
2. Запустите проект лаунчером на серверном компьютере.
3. На другом компьютере откройте адрес `http://<local-ip>:3000`.
4. Если сайт не открывается, разрешите входящие подключения в Windows Firewall для портов `3000` и `4000`.

Frontend автоматически использует тот же LAN-host для API, поэтому браузер другого компьютера не обращается к своему `localhost`.

## Ошибка подключения к БД

Если лаунчер пишет, что БД недоступна:

1. Проверьте, что PostgreSQL запущен.
2. Проверьте `DB_HOST` и `DB_PORT`.
3. Проверьте имя базы `DB_NAME`.
4. Проверьте пользователя и пароль.
5. Если база находится на другом компьютере, проверьте firewall и настройки PostgreSQL `listen_addresses`/`pg_hba.conf`.

Backend не запускается, пока проверка БД не пройдет успешно.

## Логи

Вкладка **Логи** показывает stdout/stderr:

- проверки БД;
- миграций;
- seed;
- backend;
- frontend.

Те же сообщения сохраняются в `launcher.log`. Секреты маскируются: `DB_PASSWORD`, `ADMIN_PASSWORD`, `JWT_SECRET`, токены и пароль внутри `DATABASE_URL`.

## Сборка exe

Установите PyInstaller:

```powershell
py -3 -m pip install pyinstaller
```

Соберите exe:

```powershell
.\scripts\build-launcher.ps1
```

Результат:

```text
dist/DiplomLauncher.exe
```

Для эксплуатации рядом с exe должны быть доступны:

- `apps/api`
- `apps/web`
- `apps/api/.env`
- `apps/api/node_modules`
- `apps/web/node_modules`

Если зависимостей нет, установите их заранее:

```powershell
cd apps/api
npm install
cd ../web
npm install
```

Production-сборки `apps/api/dist` и `apps/web/.next` желательны, но лаунчер может собрать их сам при первом запуске.
